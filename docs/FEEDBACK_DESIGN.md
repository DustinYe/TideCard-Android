# 云端诊断反馈建议

状态：设计建议，当前客户端没有上传入口，也没有部署接收服务。

用户逐渐增多后，集中反馈有助于收集完整版本与失败阶段、关联同类问题、记录处理状态，减少维护者逐个索取日志。建议先做用户主动提交的脱敏诊断。

## 用户流程

1. 在连接诊断中点击“提交问题”，自动整理诊断并允许补充机型、系统版本和操作描述。
2. 展示本次实际提交内容、接收方和保留期限；用户确认后通过 HTTPS 上传。
3. 返回反馈编号，用户可复制编号供维护者关联；提交失败时继续提供本地复制 / 导出。

## 数据范围

采用固定字段白名单：工具 / APK 版本、Windows 版本与架构、客户端自检和设备查询分类、ADB 服务探测分类、USB 候选接口类别 / VID / PID / MI / 驱动错误码，以及脱敏异常类型与方法名。机型与 ColorOS / Android 版本由用户确认，不能将某个厂商 VID 当成具体机型。

不接收手机序列号、手机号、IMEI、IMSI、SIM 号码、完整 PnP 实例、电脑用户名 / 完整文件路径、ADB 密钥、配对码、激活令牌或未筛选的原始命令输出。异常堆栈也需要去除路径和可能携带用户信息的异常消息。

## 维护者后台

只有经过登录授权的维护者可查看，按版本、失败阶段和厂商线索筛选、标记处理状态；默认建议保留 30 天，期限与删除方式需要在上传前说明。原始日志不直接发布到公开仓库 Issue。若后续需要公开问题摘要，应另行处理脱敏与公开授权。

接收端必须重新校验字段、限制大小与提交频率，并防止滥用；客户端不内置 GitHub 写入令牌或后台管理凭据。正常 HTTPS 请求会向服务器 / 云服务暴露来源 IP，服务端访问日志与保留策略也应纳入说明。

实施前还需要确定托管账号、私有存储与后台登录方式，并完成真实上传 / 权限 / 删除验证；不能只放一个尚无可用接收端的“上传成功”界面。
