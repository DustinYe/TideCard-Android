## 2.2.1 重装后配置接续

用户卸载重装 2.2.0 后，应用私有恢复快照已丢失，系统双卡仍保留三个字段的美国临时覆盖；原实现将其误判为其他工具覆盖并拒绝开始。2.2.1 已签名覆盖安装到同一台 HyperOS 3 / Android 16 手机。

- 对此次实际重装后的状态，只读 `prepare` 识别出兼容残留，从未覆盖的系统配置层重建两张卡原始地区为 CN 的快照；准备过程保持当前 US 配置，也未擅自建立运行会话。
- 通过真实主页播放键接续双卡 US，再点击停止，两张卡均恢复为 CN。
- 再次启动 US，测试仅移除应用恢复快照并停止检查服务，模拟相同备份丢失条件；重新启动能再次接续，停止再次恢复 CN。测试没有再卸载应用或删除完整用户数据。
- 最后重新保留双卡 US 运行会话，快照中的原地区均为 CN；配对身份和激活凭据保持不变。
- Java 解析检查通过：已知三字段残留可识别；额外字段、重复键、不完整覆盖、错误名称/布尔值和无法解析内容不会被当作可接续覆盖；原配置层优先级、缺失层拒绝及卡槽边界正确。还读取了本机真实 dump 验证原配置与覆盖层分离，未将设备 dump 纳入源码。
- 实机 Android MCC 映射方法采用 String 参数；实现兼容旧版 int 参数，并优先使用原运营商配置明确提供的国家码，未采用网络所在国家或硬编码 CN。
- Release、测试 APK 构建和 lint 通过，0 errors / 32 warnings。签名证书不变，无新增权限。

兼容接续不证明残留一定属于本应用，也不覆盖额外字段或持久修改。原系统配置或 SIM 地区无法核对时保留现状；其他 ROM 和更多 SIM 组合尚未实测。

## 2.2.0 通知设置

已签名覆盖安装到同一台 HyperOS 3 / Android 16 手机，沿用原签名证书。

- 主页入口可打开通知设置。页面完整显示两个独立开关，已在实机截图中检查布局。
- 实际点击“持续改卡通知”开启、关闭；系统类别重要性和开关回读一致，通知实际重新出现及撤下。关闭时 `KeepService` 保持前台运行，原有会话未停止。
- 修改过程保留原通知声音、振动、灯光、角标、免打扰、锁屏显示和分组等其他属性，只改变本应用固定通知类别的重要性；不接受任意目标应用或通知类别。
- 关闭状态在 Activity 重新创建后保持。重新开启保留先前通知级别，系统总通知权限被关闭时需用户重新允许。
- “配对时显示超级岛”选择持久化；关闭时普通配对通知直接包含 RemoteInput，现有配对通知即时取消提升；开启时可重新请求实况展示。
- 在超级岛关闭状态下注入配对成功 UI，成功反馈没有重新请求提升，通知按时清理。此项为 UI 状态测试，不是又一次真实密码学配对测试。
- 非法通知级别被拒绝。原国家/卡槽选择、运行快照、恢复待处理状态和配对身份在测试前后保持；系统双卡国家码仍为 `us,us`。
- Release 构建、测试 APK 构建和 lint 通过，0 errors / 30 warnings。未新增 Android 权限。

持续改卡通知和超级岛可分别选择，测试结束恢复原有选择。其他 ROM 的直接通知类别修改若不可用，使用页面内的系统设置入口。2.2.0 的签名 APK、对应源码和校验文件随 GitHub Release 提供。

## 2.1.0 配对实况通知

已在同一台小米 2304FPN6DC / 原厂 HyperOS 3 / Android 16 上签名覆盖安装：

- 原生 Android Live Update 在桌面显示为小米超级岛，系统通知记录确认已提升展示。
- 实测无线调试设置页面会隐藏岛和第三方输入浮窗；应用最终移除了浮窗实现及其权限。
- 实况通知中的 RemoteInput 被系统隐藏，与 Android 16 CDD 规定一致。点击标准“打开配对输入”操作后，同一条通知转为普通通知，展开后可使用 SystemUI 输入六位码。不会打开应用 Activity，也不会使系统配对窗口失效。
- 通过上述普通通知输入完成一次真实 TLS / SPAKE2 配对，系统设置保持为前台 Activity。随后本机无线调试成功启动新版专用后台，主界面显示已激活。
- 成功反馈约两秒后，配对通知自动撤下；后台启动进度若仍存在，只使用普通通知。日常改卡通知不提升为岛。
- UI 状态注入检查验证四个勾选图标帧依次发布、反馈结束不再提升、取消与超时移除通知、晚到网络失败不能重建已取消的通知。实机截图确认成功勾选岛曾显示并自动消失；实际图标帧的过渡由系统控制，不保证逐帧可见。
- 过期会话操作与不足六位的码被拒绝；配对码不存储、不输出日志。
- 测试保留用户已有美国双卡会话，国家码测试前后均为 `us,us`；快照、卡槽选择、配对身份和恢复待处理状态未被测试覆盖。
- Release 构建与 lint 通过，0 errors / 26 warnings。签名证书沿用原版。

没有把“岛内直接输入”标为已实现；当前 ROM 的可用路径需要切换到系统普通通知输入。未验证其他 ROM 的岛样式或 Android 17。2.1.0 的配对实况改动随 2.2.0 一并发布。

参考：[Android Live Updates](https://developer.android.com/develop/ui/views/notifications/live-update)、[Android 16 CDD](https://source.android.com/docs/compatibility/16/android-16-cdd)、[小米超级岛开发指南](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2131)。

## 功能实测

2.0.0 核心功能在小米 2304FPN6DC、原厂 HyperOS、Android 16 / API 36、无 Root 的设备上完成：

- 系统配对窗口保持打开，通过应用通知输入配对码成功。
- 外部 Shizuku 服务停止，原专用后台结束后，应用通过已保存身份独立无线启动新后台，后台实际 UID 为 2000。
- 加密保存的 ADB 身份可重新载入，公钥一致。
- 卡 1 切 JP、卡 2 切 US、双卡切 JP，分别读回实际系统国家码；单卡操作不改变另一卡。
- 每次停止均恢复两张卡原国家码；最终临时和持久覆盖均为空。
- 注入配置偏离后，持续检查自动修复目标国家码。
- 模拟后台断开时保留恢复快照，重连后通过通知停止恢复。
- 地区列表包含 10 个选项，选择和保存有效。
- 在本次 HyperOS 设备上，关闭无线调试后已启动后台仍可继续工作。
