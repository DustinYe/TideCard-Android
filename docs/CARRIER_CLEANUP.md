# 清除旧地区配置

2.4.3 新增用户主动确认的旧配置清除，适用于地区读取异常（例如 `717`）、其他工具失败后残留或旧版本遗留。无法从残留内容确认写入者，不会将所有异常归因于 NFR 或某个品牌。

## 使用

1. 覆盖安装同签名新版，重新激活内置后台，确保后台也运行新版代码。先停止其他改卡工具，避免重复写入。
2. 从主界面“清除旧地区配置”或“设置 → 旧地区配置”进入。
3. 选择双卡、卡 1 或卡 2，点击“检查旧配置”。空卡槽跳过，检查本身只读。
4. 核对卡槽、当前国家码与恢复目标，点击“一键清除旧配置”，在确认框中确认。
5. 等待显示国家码已核对，返回主界面重新选择地区并开始。

潮汐当前存在会话、恢复快照或待恢复状态时不可清除，先按原流程停止并恢复。不会删除恢复快照来绕过限制。检查失败时不会提供确认清除入口。

## 范围和限制

- 仅接收 `sim_country_iso_override_string`、`carrier_name_override_bool`、`carrier_name_string`，允许只存在其中部分字段，也允许待丢弃的异常值。自动接续会话的识别规则没有放宽。
- 临时和持久层必须都能解析且仅包含上述字段；APN、VoLTE / IMS 等其他字段、重复键及未知格式均拒绝。选择双卡时，任一所选卡的检查失败会在写入前阻止全部处理，可改选另一卡单独检查。
- 恢复基线由 CarrierConfig 默认值、平台和运营商层按优先级重建；原始国家码必要时通过 SIM MCC 与系统 MCC 表核对，不能直接把异常读数当作基线，也不统一写死为 CN。
- 确认后先以非持久方式写入原地区和名称，等待国家码回读，再重新检查覆盖并清除。没有持久残留时仅请求非持久 null 清除；仅确有持久残留时请求 null + persistent=true。正常改卡仍不写入持久配置，兼容桥拒绝任何携带配置的持久写入。
- 部分 ROM 不允许普通应用清除持久覆盖。遇到权限拒绝、超时或异常回读时显示“未完成”，保留可检查的现场；可能已完成前面的卡槽，或已写回原地区但尚未清除覆盖。重新检查可区分当前状态，不假报全成功。
- 系统 CarrierConfig API 没有跨卡槽事务，也没有原子比较并清除接口。写入前检查和中途重验可检测大部分变更，但其他工具同时写入仍有竞争窗口，所以应先停止其他工具。
- 检查计划保留在专用后台内存中，使用随机令牌，2 分钟有效且仅能消费一次；确认前重新核对所选卡槽、订阅、两层覆盖和基线。更新、换卡或配置变化后重新检查。

数据在手机本地处理，不上传完整 dump、令牌或配置。页面只展示卡槽、受限格式的国家码、恢复目标及覆盖类别，不暴露 SIM 序列号。

## 验证边界

主机模拟覆盖异常 / 部分字段、持久残留、第三方字段保护、过期 / 重放、换卡、并发变化、部分失败、回读超时及两卡幂等清除。Android 11 / 14 的界面 / 控制器测试使用模拟后台，不执行真实 SIM 写入、ADB 或权限委派。本次没有可连接的手机，另一台 OPPO 的真实清除效果仍待用户验证。

参考：[Android CarrierConfigLoader](https://android.googlesource.com/platform/packages/services/Telephony/+/refs/heads/main/src/com/android/phone/CarrierConfigLoader.java)、[NFR 官方配置与恢复实现](https://github.com/Ackites/Nrfr/blob/master/app/src/main/java/com/github/nrfr/manager/CarrierConfigManager.kt)。NFR 的 null 持久恢复用于理解系统接口语义，本功能未复制其实现。
