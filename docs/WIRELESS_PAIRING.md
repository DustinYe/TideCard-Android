# 无线配对等待问题与 2.4.2 修复

用户提供的 OPPO A3x 5G 照片已显示系统配对码，应用通知却停在等待状态。这证明系统具备配对入口，但不证明应用成功发现或连接了配对服务。该手机与朋友的电脑都不在开发现场。

## 已确认的代码问题

旧版只有在 mDNS / NSD 自动发现配对端口后才提供通知输入按钮。发现失败时，系统配对弹窗已经打开，通知仍只提供等待与取消；应用内手动入口需要切换页面，容易使系统配对弹窗失效。

此外，旧解析队列依赖系统回调推进，没有超时机制；一个服务解析没有返回，会阻塞后续服务。失败解析没有重试，地址判断只查看一个地址。

## 使用新版

1. 覆盖安装 2.4.2，打开“激活 / 配对 → 开始配对”，再打开系统无线调试的配对码弹窗。
2. 自动发现正常时，继续在通知中输入六位码。
3. 自动发现失败时，保持系统弹窗打开，下拉并展开通知，点“手动配对”，输入 **配对弹窗底部端口 + 空格 + 当前六位码**。格式示例为 `39461 123456`；这里是示例，必须使用系统当前显示的真实值。
4. 使用实况通知 / 超级岛时，先点“手动配对”，同一条通知会转为普通通知；再次展开后使用系统的输入框。不会打开应用 Activity，不需要分屏、悬浮窗或无障碍权限。
5. 配对成功后，如果仍未发现连接端口，关闭配对弹窗，读取无线调试主页面的 IP 地址和端口。在普通通知点“输入连接端口”，只填主页面端口。配对端口与连接端口用途不同，不能混用。
6. 端口发生变化时，重新填写当前值；也可点“重新搜索”。取消或超时后需要重新开始配对。

手机 VPN / 加速器可能影响自动发现。Android 13 及以上优先在 Wi-Fi 网络上发现服务；手动输入仅连接 `127.0.0.1`，不允许填写其他设备 IP。此改动不保证兼容所有 VPN 或 ROM 的网络限制。

## 实现与隐私

- 通知在未发现端口时也提供手动输入；配对后的连接同样有通知内补填入口。
- 配对输入只接受有效端口和六位 ASCII 数字，保留前导零。原始配对码不进入状态提示、偏好、Intent 路由或日志。
- 输入操作绑定当前激活会话，忙碌、成功反馈与过期会话不能重复提交。通知刷新复用当前会话的输入令牌，不因状态刷新取消正在使用的令牌；不同会话仍隔离。
- NSD 队列去重并限制长度，解析 8 秒超时，每个失败最多两次尝试；Android 14 及以上尝试取消超时解析。迟到回调不能完成新请求。Android 14 及以上检查服务提供的多个地址，继续只接受本机地址。
- 本版不添加云端日志上传，不改变改卡或恢复逻辑，也不修改 Windows 网络配置。

## 验证与限制

主机 JVM / Robolectric 测试覆盖输入格式、队列、Android 11 / 14 通知与服务行为，包括未发现端口时经 RemoteInput / Receiver 提交、配对后补填连接端口、会话隔离、重试和取消。测试屏蔽原生配对任务，不在电脑 JVM 中进行真实 TLS / SPAKE2 或手机激活。

Release APK、Android 仪器测试包与 lint 构建检查通过，沿用原签名。没有连接手机执行新一轮实机配对，OPPO 的系统通知渲染、输入体验、mDNS 与真实激活仍需该手机验证。
